# KoletPay — responsive Next.js web frontend

This repository is the **frontend-only** hackathon prototype of KoletPay, an invoice, customer-ledger and business-insights web application for Nigerian SMEs.

It is a **responsive web application** (works in browsers on laptops, tablets and phones), **not** a native mobile application. It has one responsive Home dashboard; there is no separate desktop-dashboard product or mobile-codebase.

## Run

```bash
npm install
npm run dev
```

Then visit [http://localhost:3000](http://localhost:3000). Requires Node.js 20 or newer.

## What's in the frontend

- Home with daily, monthly and yearly revenue views, recent invoices, top customers and popular products
- Customer ledger: add/edit customers, contact info, current project, notes, order and payment history
- Product/service catalogue with prices
- Invoice creation with multiple line items and automatic totals
- Invoice details and simulated partial/full payment tracking
- Pay-in-parts schedule calculator (exact integer-naira rounding, simulated first payment)
- Transaction logbook, reports and CSV export
- Rule-based local assistant for demo queries and invoice draft creation; browser voice input when supported
- Business profile page

All data is **sample data** and persists only in the browser using `localStorage` (`lib/store.tsx`). Refreshing the page keeps changes; switching browsers or clearing browser data won't. Select **Settings → Reset sample data** to restore original data.

## Backend integration points

The backend team can swap the `lib/store.tsx` implementation with HTTP calls and a server cache (or React Query) while retaining the UI. Suggested endpoints:

| Method | Route | Purpose |
|---|---|---|
| GET | `/api/business/me` | Get business profile |
| PATCH | `/api/business/me` | Update business |
| GET/POST | `/api/customers` | List/create customers |
| GET/PATCH | `/api/customers/:id` | Customer profile |
| GET/POST | `/api/products` | Catalogue |
| GET/POST | `/api/invoices` | List/create invoice |
| GET | `/api/invoices/:id` | Invoice with payments |
| GET | `/api/payments` | Transaction logbook |
| GET | `/api/reports?period=day|month|year` | Aggregated totals |
| POST | `/api/assistant/parse-invoice` | Optional real AI parsing |

Types and money calculations live in `lib/types.ts`; demo selectors live in `lib/metrics.ts`. For real ALATPay integration, **only the backend** should handle credentials, signature validation and webhook reconciliation. Replace `simulatePayment` with a backend-confirmed payment state; the demo does **not** move real money.

## Data and security notes

- The names/phone numbers in seed data are fictitious sample data. Do not enter sensitive real customer data into this demo on a shared device.
- Demo invoice pages (`/invoices/:id`) are **not** public payment pages. Real public links must be securely generated by the backend team, with authentication/authorization as appropriate.
- Contact details and purchase history should be stored and processed with appropriate customer notice, consent and access controls in production.
- `mailto:` drafts an email in the user's mail app; this app does not send emails or WhatsApp messages.
- Reports reflect recorded demo transactions, not official bank statements, and do not guarantee loans or grants.

## File structure

- `app/` — Next.js App Router routes and responsive CSS
- `components/Shell.tsx` — shared web navigation, headers and UI primitives
- `components/RevenueChart.tsx` — simple responsive revenue chart
- `lib/seed.ts` — initial demo business records
- `lib/store.tsx` — replaceable local data layer
- `lib/metrics.ts` — computed reports/customer totals
- `lib/types.ts` — data schema, amounts, payment status
